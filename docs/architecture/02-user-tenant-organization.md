# 用户、租户与组织设计

- 状态：架构基线 v1（已确认）
- 适用范围：认证、用户、部门、租户、平台运维
- 所有者：GovData Platform Team
- 最后更新：2026-08-01

## 模型

- Tenant 表示独立地区，是数据和授权的硬隔离边界。
- Human Account 当前由 `sys_user + Sa-Token` 管理。
- 一个账号属于一个租户、一个主部门，可以拥有多个角色。
- 跨部门访问通过 Role、Policy 或 AuthorizationGrant，不通过多部门归属隐式获得。
- 同一自然人在不同地区使用独立账号；第一阶段不建设跨租户统一人员主档。

授权层使用统一 Principal：

```text
HUMAN       人员账号
SERVICE     系统、集成或后台任务身份
AGENT       具有独立标识的 AI Agent
```

## 管理员分离

- 平台运维管理员管理租户、系统配置和运行健康，默认无租户业务数据权限。
- 租户管理员只管理当前地区的用户、部门、角色和授权。
- 框架超级管理员不得自动绕过数据资源 ABAC。
- 跨租户排障只能通过审批、限时、默认只读且强审计的 BreakGlass Access。

## 组织变化

- 部门保存稳定编码、行政区划编码和树路径。
- 部门撤销或迁移不物理破坏历史授权和审计引用。
- 审计记录主体和部门必要快照，避免后续更名导致历史不可读。
- 未来出现多岗需求时可新增 PositionAssignment，但不自动授予数据权限。

## 安全不变量

- 所有租户业务表和缓存键包含可信 tenantId。
- tenantId 从认证上下文获得，不信任客户端任意参数。
- SERVICE 和 AGENT 不使用人员共享账号。
- 被禁用主体、租户或部门相关 Grant 立即失效。
