# 查询访问审计表评审

- 所有者：`govdata-query`
- 类型：租户内追加记录；不使用逻辑删除、更新审计字段或乐观锁。
- Baseline：`script/sql/baseline/33_govdata_query.sql`
- 已部署环境：`script/sql/upgrade/20260906_001_create_query_access_log.sql`

## 记录语义

每次查询生成服务端 `query_id`。外部调用前独立短事务追加 `STARTED`，随后追加
`SUCCEEDED`、`DENIED` 或 `FAILED`；同一查询两条记录不可覆盖。仅有开始事件表示执行尚未结束，
或发生了进程退出/结束审计故障，不能直接推定查询成功。

主键使用有符号 bigint 雪花 ID。`trace_id` 关联授权决策审计与 Secret 访问审计。
查询审计只保存主体、资源、用途编码、数量、耗时和稳定错误码，不保存 SQL、字段值、结果、连接串或凭据。
启动审计失败不执行外部查询，结束审计失败不交付查询结果。外部调用不进入控制库事务。

## 查询与索引

| 查询 | 索引 |
| --- | --- |
| 租户时间范围检索、归档 | `(tenant_id, occurred_time, access_log_id)` |
| 开始/结束事件关联 | `(tenant_id, query_id, access_log_id)` |
| 指定资源访问追溯 | `(tenant_id, resource_id, occurred_time, access_log_id)` |

不建物理外键，不跨领域 JOIN 业务表。错误码来自所属模块，结果和主体类型使用命名 CHECK。
运行时 Mapper 只提供 INSERT；尚未提供审计管理页面和日常 UPDATE/DELETE API。

## 容量、保留与清理责任

容量预算以每日 10 万次查询、20 万条事件为起点，单条约 0.5–1 KB（含索引需以实测校准），
约 100–200 MB/日。实际吞吐超过预算时应评估归档和独立分析读模型，不用控制库做无界历史统计。

- 成功事件在线保留至少 180 天；失败、拒绝及未闭环开始事件至少 365 天。
- 归档至受控对象存储至少 3 年；适用法规、合同要求更长时取更长期限，法律保全记录不得清理。
- 归档完整性校验、恢复演练和保留策略审批由平台运维与 `govdata-query` 负责人共同承担。
- 本次不启用自动清理。后续清理必须由所属模块按租户、到期时间和明确主键批次执行，单批最多
  5000 条；仅处理已归档且校验成功的已闭环查询，监控清理量、失败量和未闭环数量。

## 发布边界

先按升级规范备份、记录 checksum 并执行新表脚本，再部署 Adapter。回退应用时保留表和审计记录。
测试只操作显式启用的随机临时库；不自动迁移现有开发库或生产库。
