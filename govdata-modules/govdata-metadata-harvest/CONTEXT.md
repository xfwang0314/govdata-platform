# govdata-metadata-harvest 模块上下文

- 状态：单数据源批量采集模型改造中
- 所有者：GovData Platform Team
- 最后更新：2026-08-23

## 职责

- 每个计划绑定一个数据源；同一数据源可以按范围和调度配置多个计划。
- 保存不可变计划配置修订、过滤规则、手工/Cron运行、最终失败明细和可选原始批次归档。
- 调用数据源 Connector 分批发现命名空间和完整表结构，过滤后通过稳定契约提交目录模块。
- 同一数据源运行串行；失败重跑整次，不提供通用断点续采。
- 业务只依赖 `HarvestScheduleRegistrar`；默认 Quartz Adapter 负责 Cron、Misfire 和触发，后续可替换其他调度实现。
- 权威全量运行的大规模资产消失会进入 `ANOMALOUS`，保留原技术状态并等待核对后整次重跑。

## 边界

- 不访问数据源或目录模块的 Mapper/Entity/业务表。
- 外部 JDBC/对象存储调用位于数据库事务外；目录写入使用有界短事务。
- 只有完整成功运行可触发缺失检测；部分成功批次不回滚已生效的表。
- 规则不执行任意 SQL、SpEL、Groovy 或 JavaScript；名称正则仅由线性时间 RE2/J 执行，创建和修改时先校验语法。

## 采集运行入口（2026-10-28）

运行记录统一从采集计划行内打开抽屉，不再提供独立采集运行页面或全部运行记录查询。
分页接口为 `GET /govdata/metadata-harvest/plans/{planId}/runs`，必需指定计划并执行计划资源查看授权；
保留状态筛选、运行详情、失败明细及整次重跑。运行数据与采集执行逻辑继续保留。
已有环境执行 `20261028_001_scope_harvest_runs_to_plan.sql`，将原菜单转换为计划下权限节点，保留角色绑定。
验收：切换两个计划应分别只展示本计划记录；状态筛选与翻页不丢失计划范围；无计划查看权限时拒绝访问。
旧 `GET /govdata/metadata-harvest/runs` 不再提供列表接口。
